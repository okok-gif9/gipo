# تنظیم پروژهٔ Supabase گیپو

پروژهٔ مستقل با نام `gipo` در سازمان Supabase کاربر ایجاد می‌شود. تنظیمات هدف شامل فعال‌بودن Data API، غیرفعال‌بودن «Automatically expose new tables» و فعال‌بودن Automatic RLS است. منطقهٔ هدف، `eu-central-1` (Frankfurt) است تا به کاربران هدف نزدیک‌تر باشد.

در فرم ایجاد پروژه، گزینهٔ عمومی Europe انتخاب شد و یک گذرواژهٔ قوی با مولد داخلی Supabase ساخته شد. مقدار گذرواژه در کد، مستندات یا تنظیمات پروژه ذخیره نمی‌شود.

گزینهٔ «Automatically expose new tables» غیرفعال شد تا هر جدول فقط پس از تعریف صریح سیاست‌های دسترسی در دسترس API قرار گیرد.

پروژه با موفقیت ساخته شد و وضعیت آن Healthy است. مرجع عمومی پروژه `mowpakpysuzbnogijucw` و منطقهٔ نهایی آن Central EU (Frankfurt) است.

مهاجرت محلی در `supabase/migrations/0001_gipo_schema.sql` نگه‌داری می‌شود. به‌دلیل محدودیت زمانی ورودی SQL Editor در مرورگر، اجرای آن به بخش‌های کوچک‌تر و قابل‌راستی‌آزمایی تقسیم می‌شود.

ویرایشگر SQL از Monaco استفاده می‌کند و متن نیمه‌کارهٔ ورودی قبلی در مدل فعال شناسایی شد؛ برای جلوگیری از اجرای ناقص، این متن با بخش‌های کامل مهاجرت جایگزین می‌شود.

بخش نخستِ مهاجرت با موفقیت اجرا شد و جدول‌های `profiles`، `story_bots` و `story_bot_access` به‌همراه افزونهٔ UUID و شاخص‌های مرتبط ایجاد شدند.

بخش دوم نیز با موفقیت اجرا شد و جدول‌های اجرای داستان، پیام‌ها، تنظیمات یکپارچه، اتصال تلگرام، ثبت رویدادهای تلگرام و ترجیحات پیگیری ساخته شدند.

بخش نهایی با موفقیت اجرا شد: ایجاد خودکار پروفایل هنگام ثبت‌نام، تریگرهای `updated_at` و سیاست‌های RLS برای مالکیت، دسترسی خصوصی/عمومی و حافظهٔ اجرای داستان فعال هستند.
